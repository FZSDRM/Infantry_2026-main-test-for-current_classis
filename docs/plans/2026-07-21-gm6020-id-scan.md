# GM6020 ID Scan Implementation Plan

> **For implementer:** Use TDD throughout. Write failing test first. Watch it fail. Then implement.

**Goal:** Add a safe, remotely armed CAN2 GM6020 ID 1–7 scan that rotates each online motor forward 10° and back to its origin at no more than 10°/s.

**Architecture:** A pure C state machine owns sequencing, timeouts, and speed commands and is tested on the host. The existing `gimbal.c` contains two compile-time branches selected by `GM6020_ID_SCAN_MODE`: the scan branch registers seven GM6020 instances and maps state-machine actions to the DJI motor API, while the normal branch retains the original yaw/pitch control.

**Tech Stack:** STM32F407 HAL, FreeRTOS/CMSIS-RTOS, existing DJI motor/CAN framework, Arm GNU Toolchain, host GCC, PowerShell 7 contracts.

**Files:**

- Create: `tests/gm6020_id_scan_logic_test.c`

**Step 1: Write the failing host test**

Create a table-driven C test with a small `ASSERT_TRUE` macro. It must include `gm6020_id_scan_logic.h` and cover these independent behaviors:

1. disabled input returns `STOP_ALL`, resets to `DISARMED`, and selects index 0;
2. first enabled step enters `WAIT_ONLINE` without moving;
3. an online motor captures its start angle and commands exactly `+10.0f` dps;
4. reaching start + 10° changes the command to exactly `-10.0f` dps;
5. returning to the configured origin tolerance stops the current motor and enters settling;
6. a 1000 ms offline timeout stops/skips the motor;
7. a 3000 ms forward or reverse timeout stops/skips the motor;
8. advancing after ID 7 enters `COMPLETE` and keeps all motors stopped;
9. `COMPLETE` cannot restart while still enabled, but a disabled step rearms the scanner;
10. speed output never exceeds the configured 10°/s limit.

The public API must be exercised as:

```c
GM6020IDScanLogicConfig config = {
    .motor_count = 7,
    .max_speed_dps = 10.0f,
    .travel_deg = 10.0f,
    .origin_tolerance_deg = 0.5f,
    .online_timeout_ms = 1000,
    .motion_timeout_ms = 3000,
    .settle_ms = 300,
};
GM6020IDScanLogic context;
GM6020IDScanInput input;
GM6020IDScanOutput output;

GM6020IDScanLogicInit(&context, &config);
output = GM6020IDScanLogicStep(&context, &input);
```

**Step 3: Implement the minimal state machine**

Define:

```c
typedef enum {
    GM6020_SCAN_DISARMED,
    GM6020_SCAN_WAIT_ONLINE,
    GM6020_SCAN_FORWARD,
    GM6020_SCAN_REVERSE,
    GM6020_SCAN_SETTLE,
    GM6020_SCAN_COMPLETE,
} GM6020IDScanState;

typedef enum {
    GM6020_SCAN_ACTION_NONE,
    GM6020_SCAN_ACTION_STOP_ALL,
    GM6020_SCAN_ACTION_STOP_CURRENT,
    GM6020_SCAN_ACTION_RUN_CURRENT,
} GM6020IDScanAction;
```

The context stores the copied config, state, zero-based motor index, state-entry timestamp, and captured start angle. The input stores `enabled`, `online`, `now_ms`, and `angle_deg`. The output stores action, motor index, and speed reference.

Use elapsed-time subtraction on `uint32_t` so wraparound remains defined. A helper advances the index or enters `COMPLETE`. Clamp every run output to `[-max_speed_dps, +max_speed_dps]`. Disabled input always wins and resets the full context.

**Step 4: Compile and run — confirm GREEN**

Compile with the command above, require exit 0, then run the produced executable and explicitly require `$LASTEXITCODE -eq 0`.

Expected output: `GM6020 ID scan logic tests passed.`

Commit only the two logic files and host test with OMC trailers. Do not stage `.gitignore` or `application/gimbal/gimbal.c`.

**Step 3: Implement minimal hardware integration**

Add enabled defaults in `robot_def.h`:

```c
#define GM6020_ID_SCAN_MODE
#define GM6020_ID_SCAN_FIRST_ID          1u
#define GM6020_ID_SCAN_LAST_ID           7u
#define GM6020_ID_SCAN_MAX_SPEED_DPS     10.0f
#define GM6020_ID_SCAN_TRAVEL_DEG        10.0f
#define GM6020_ID_SCAN_ORIGIN_TOL_DEG    0.5f
#define GM6020_ID_SCAN_ONLINE_TIMEOUT_MS 1000u
#define GM6020_ID_SCAN_MOTION_TIMEOUT_MS 3000u
#define GM6020_ID_SCAN_SETTLE_MS         300u
#define GM6020_ID_SCAN_CURRENT_MAX_RAW   3000.0f
```

The scan branch in `gimbal.c` must:

- call `INS_Init()` once;
- configure and register seven CAN2 `GM6020_CURRENT` motors in a loop;
- configure only the motor-feedback speed loop, with a modest proportional gain, no integral/feedforward, and output limit `GM6020_ID_SCAN_CURRENT_MAX_RAW`;
- set every initial speed reference to zero and call `DJIMotorStop()`;
- subscribe to `gimbal_cmd` and publish `gimbal_feed`;
- treat `gimbal_mode != GIMBAL_ZERO_FORCE` as enabled;
- call `DJIMotorIsOnline()` and pass the selected motor's total angle into the pure state machine;
- require `DJIMotorHasFeedback()` as well as `DJIMotorIsOnline()` before passing `online = 1`; daemon's registration-time ONLINE value alone must never start a motor;
- translate `STOP_ALL`, `STOP_CURRENT`, and `RUN_CURRENT` actions without ever enabling two motors at once;
- clamp speed before setting it;
- publish the INS attitude every task iteration and use ID1's single-round angle for compatibility.

Wrap the scan and normal gimbal implementations with `#ifdef GM6020_ID_SCAN_MODE` / `#else` in `gimbal.c`. Preserve the user's existing commented `MotorOfflineAlarmTask()` line in the normal branch.

Update `verify_gimbal_vision_runtime.ps1` so the alarm task call is asserted inactive rather than required; keep the remaining gimbal/vision runtime requirements unchanged.

In `dji_motor.c`, replace the stopped-motor buffer clear length `16u` with `2u` so only one current-command slot is cleared.

Add a zero-initialized `feedback_received` member to `DJIMotorInstance`, set it after the first successful `DecodeDJIMotor()` frame, and expose a read-only `DJIMotorHasFeedback()` query for the scanner.

Add `gm6020_id_scan_logic.c` to `Makefile`.
