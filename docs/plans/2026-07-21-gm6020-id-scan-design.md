# GM6020 ID 遍历测试设计

## 目标

在 `feature/gimbal-vision-only` 分支增加 GM6020 ID 遍历测试模式：在 CAN2 上依次检查 ID 1–7，每个在线电机以不超过 `10°/s` 的速度正转 10°，随后反转回起始角度，再切换到下一个 ID。

## 约束

- 保留现有遥控器、图传遥控器和视觉通信链路。
- 只有原控制逻辑解除 `GIMBAL_ZERO_FORCE` 后才启动扫描。
- 遥控器失能时立即停止所有扫描电机并复位扫描状态。
- 不改动或提交用户当前在 `application/gimbal/gimbal.c` 中注释 `MotorOfflineAlarmTask()` 的未提交修改。
- 不烧录硬件；本次验证止于主机单元测试、静态契约和固件构建。

## 方案选择

采用“预注册 ID 1–7 + 独立扫描状态机”方案。

未采用的方案：

- 上电立即自动运行：绕过现有失能保护，机械风险较高。
- 运行时动态修改一个电机实例的 CAN ID：现有 CAN 回调与发送分组在注册时确定，动态改 ID 会破坏注册关系。
- 直接发送裸 CAN 电流：无法可靠使用反馈角度控制 10° 行程，也难以约束最大速度。

## 软件结构

### 独立路由

新增 `application/gimbal/gm6020_id_scan.c/.h`，并通过 `robot.c` 中的编译条件路由：

- `GM6020_ID_SCAN_MODE` 开启时调用 `GM6020IDScanInit()` 和 `GM6020IDScanTask()`。
- 宏关闭时继续调用原 `GimbalInit()` 和 `GimbalTask()`。

扫描功能不直接修改 `gimbal.c`，从而保留用户正在进行的本地调试改动。

### 纯状态机

新增与 HAL/FreeRTOS 无关的 `gm6020_id_scan_logic.c/.h`。状态机接收时间、使能状态、当前 ID 在线状态和反馈角度，输出当前电机索引、速度目标、启动/停止命令。

状态如下：

1. `DISARMED`：全部停机，等待原控制链路解除零力矩。
2. `WAIT_ONLINE`：等待当前 ID 反馈，最多 1000 ms；超时则跳过。
3. `FORWARD`：记录起始多圈角度，以 `+10°/s` 运行到相对 `+10°`。
4. `REVERSE`：以 `-10°/s` 返回起始角度。
5. `SETTLE`：停止当前电机并等待 300 ms，再切换下一个 ID。
6. `COMPLETE`：全部停止，直到出现一次失能后才能重新开始。

正转或反转阶段最多允许 3000 ms。电机中途离线或阶段超时会立即停机并切换到下一个 ID。

## 电机配置

- 总线：CAN2。
- ID：1–7。
- 类型：`GM6020_CURRENT`。
- 控制：电机自身反馈的速度闭环，不启用角度环或前馈。
- 速度目标由状态机产生，并在硬件适配层再次钳制到 `[-10, +10]°/s`。
- 速度 PID 最大输出保守限制为 3000 CAN 原始值。
- 非当前电机保持 `DJIMotorStop()`，不参与闭环输出。

扫描模块仍初始化 INS 并发布 `gimbal_feed`，保证 RobotCMD 与视觉姿态数据链继续获得有效云台 IMU 数据。ID1 的单圈角度用于兼容现有 `yaw_motor_single_round_angle` 字段。

## 安全修正

现有 `DJIMotorControl()` 在处理停止电机时，从单个电机槽位起始位置清零 16 字节，超过一个 8 字节 CAN 数据帧。扫描模式会频繁停止多个电机，因此必须把该清零长度修正为当前电机槽位的 2 字节，避免越界和误清其他内存。

## 测试策略

1. 主机 C 单元测试先失败，再实现纯状态机；覆盖失能复位、10°/s 限速、正转到反转、回原点、离线跳过、运动超时、完成后锁存和重新使能。
2. PowerShell 静态契约先失败，再实现硬件集成；覆盖 ID 1–7、CAN2、速度闭环、3000 输出限制、宏路由和 `DJIMotorStop()` 两字节清零。
3. 复跑现有命令链路与运行时契约。
4. 使用 Arm GNU Makefile 完整构建，并审计 ELF 符号、提交范围和工作区状态。
5. 实板验证需另行执行，重点确认电机方向、实际速度、回零误差、ID 对应关系和机械限位。
